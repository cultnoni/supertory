# 슈퍼토리 장르문학 피드백 파이프라인 설계

Oct 24, 2026 · 초안 (열린 질문 1~3번 결정 반영)

## 개요

장르문학(`cluster_id=genre_literature`) 작품의 첨삭 피드백을 장르별로 다르게 만든다. 방식은 일반문학 파이프라인과 같다. 기존 뼈대(규칙 검사 → AI 리포트 → AI 교정 카드 → 저장 전 검증)와 저장 구조, 히스토리, 수집, 중요도별 표시는 그대로 쓰고, 장르별 설정층(판단 기준, 프롬프트, 카드 유형, 검증 규칙)만 갈아끼운다.

목표는 "장르의 약속을 지키면서 독자가 끝까지 읽게 만드는 것"이다. 웹소설은 "더 잘 읽히게", 일반문학은 "작가가 의도한 대로 작동하게"가 목표였다. 장르문학은 그 사이다. 독자가 장르에 기대하는 약속(추리의 공정한 단서, SF의 일관된 규칙 등)이 지켜지는지를 먼저 보고, 그 약속을 작가가 일부러 깬 곳은 존중한다.

가장 큰 위험은 일반문학과 비슷하다. AI가 장르 관습을 절대 규칙처럼 들이대서 작가가 일부러 한 선택을 오류로 지적하는 것이다. 그래서 장르 약속을 판정하되, 모든 판정에 근거 위치를 붙이고 "의도라면 유지"를 허용한다.

## 현재 상태 (2026-10-24 코드 확인)

- 첨삭 피드백(`feedback_api.py`)은 `literary_track()`으로 일반문학 단편·장편·중간 점검만 갈라 보낸다. 장르문학 작품은 갈라지지 않고 웹소설 러너(`feedback_pipeline/runner.py`, 회차 단위)를 그대로 탄다.
- 웹소설 러너의 프롬프트에는 장르 정보가 거의 없다. 프로젝트 정보 줄에 `장르: …` 한 줄이 들어가는 정도다(`feedback_pipeline/context.py`). 설명 강도(`explanation_lens`)만 장르로 정해지고, 장르문학은 `normal`이다.
- 카드 유형은 웹소설용 8종뿐이다(`prompts/type_guidance.json`: explain_less, info_placement, action_clarity, redundancy, reader_question, abstract_expression, other, none).
- AI 패널(도우미) 프롬프트는 `prompt_pipelines.py`에서 장르문학이 웹소설과 글자까지 같은 복사본이다. `tests/test_prompt_pipelines.py`가 동일성을 강제한다. 이 설계의 범위가 아니며 3단계 이후에 따로 다룬다.
- `data/genre_playbooks.json`에는 로맨스·판타지 등 웹소설 장르만 있다. 미스터리·스릴러·SF·정통판타지·실험 기준은 없다. 장르문학 로맨스는 작품을 만들 때 로맨스 구조(정서형/사건형)와 배경(현대/사극)을 필수로 받는다(`app.py`, `genre_clusters.is_genre_literature_romance`). 이 값이 로맨스 기준집과 프롬프트에 어떻게 이어지는지는 아직 확인하지 않았다.
- 장르문학 클러스터는 숨기는 기능이 없다(`CLUSTER_HIDDEN_FEATURES["genre_literature"]`가 빈 집합). 떡밥 모음, 흥행 공식 등이 모두 보인다.

## 적용 대상과 분기

장르문학의 하위 장르 6개(`genre_clusters.CLUSTER_SUBGENRE_MAP["genre_literature"]`)를 성격이 비슷한 네 묶음으로 나눈다. 장르마다 전부 따로 설계하지 않는다.

| 묶음 | id | 하위 장르 (`main_genre`) | 판단 기준의 중심 |
|---|---|---|---|
| 수수께끼형 | `puzzle` | 미스터리·추리(`mystery`), 스릴러·호러(`thriller`) | 독자가 아는 정보의 순서, 단서의 공정성, 반전의 개연성, 긴장 곡선 |
| 세계형 | `world` | SF(`sf`), 정통판타지(`traditional`) | 세계 규칙의 일관성, 설정을 풀어 주는 방식, 개연성 |
| 문체형 | `style` | 실험(`experimental`) | 형식 파괴와 문체를 지키는 쪽이 우선. 일반문학 파이프라인 재사용 |
| 관계형 | `relation` | 로맨스(`romance`) | 인물 관계의 전개, 감정선. 기존 로맨스 기준집 재사용 |

- 판별은 `genre_track(project)` 하나로 한다(새 모듈, `literary_form.literary_track`과 같은 형태). 반환값은 묶음 id 또는 `None`. `cluster_id=genre_literature`가 아니면 `None`이다.
- 같은 묶음 안의 장르 차이는 판단 기준 표 안의 "장르별 추가" 줄과 세부장르(`sub_genre`, 예: 본격 `honkaku`, 심리 `psycho`)로 흡수한다.
- 기존 작품은 그대로 열린다. 하위 장르가 정해지지 않은 장르문학 작품은 지금처럼 웹소설 러너를 탄다.

### 묶음별로 재사용하는 엔진

| 묶음 | 엔진 | 분석 단위 |
|---|---|---|
| `puzzle`, `world`, `relation` | 웹소설 러너(`runner.run_feedback`) 위에 장르 레이어를 얹는다 | 회차 |
| `style` | 일반문학 파이프라인(`literature_runner`, `literature_long_runner`)을 그대로 쓴다 | 단편은 작품 전체, 장편은 회차(장) |

`style`이 일반문학 엔진을 쓰므로 문학처럼 단편/장편 선택(`literary_form`)과 문체 칸 6개가 따라온다. 연결은 `genre_track()`이 `style`일 때 일반문학 트랙 값(`short` / `long`)을 돌려주는 방식으로 한다. 이미 통과한 `literary_track()`은 고치지 않는다(일반문학 쪽이 다시 깨질 위험을 피한다).

나머지 세 묶음은 첫 버전에서 단편/장편을 나누지 않고 회차 단위 하나로 간다. 작품 전체를 한 번에 읽는 분석(단편용)은 나중에 필요하면 추가한다.

## 장르 레이어: 설정층 4가지

웹소설 러너의 단계마다 아래 네 가지를 장르에 맞게 끼운다.

| 설정층 | 하는 일 | 놓이는 곳 |
|---|---|---|
| 판단 기준(루브릭) | 리포트가 보는 항목과 3단계 판정 기준 | 리포트 프롬프트 |
| 카드 유형 | 장르 전용 유형 태그, 수정안/지적형 구분, 중요도 | 카드 프롬프트, `type_guidance` |
| 검증 규칙 | 저장 전에 거르는 규칙 | `checks.py` 확장 |
| 작가 선언 | 장르 약속을 일부러 깬 곳, 지키고 싶은 약속 | 설정집 칸 |

프롬프트는 `feedback_pipeline/prompts/genre/<묶음 id>/`에 둔다. 웹소설·문학 프롬프트 파일은 건드리지 않는다. 모델 선택은 `config.py`에 `GENRE_STAGE_MODELS`를 두어 단계별로 정한다. 기본은 `claude-sonnet-5`이고 비용 상한은 지금과 같은 실행당 2달러다.

판정은 문학과 같이 점수 없이 "잘 작동함 / 보완 여지 / 문제" 3단계로 하고, 모든 판정에 근거 위치(회차 번호 + 짧은 인용)를 붙인다.

## 묶음별 설계

### 수수께끼형 (미스터리·추리, 스릴러)

독자가 어느 시점에 무엇을 아는지가 핵심이다. 그래서 리포트 단계에 장면 지도 대신 「정보 공개 지도」를 먼저 만든다. 회차마다 새로 드러난 단서, 독자가 알게 된 사실, 인물이 알고 독자는 모르는 사실, 걸어 둔 의문을 뽑는다. 작가용 리포트이므로 범인·트릭을 말해도 괜찮다.

| 항목 | 보는 것 |
|---|---|
| 단서의 공정성 | 풀이에 쓰이는 단서가 독자에게 미리 공정하게 제시됐는가 |
| 정보 공개 순서 | 알려야 할 때 알리고, 숨길 때 숨겼는가 (너무 일찍/늦게 알림) |
| 복선 회수 | 걸어 둔 의문과 단서가 방치되거나 갑자기 튀어나오지 않는가 |
| 반전의 개연성 | 뒤집힌 뒤 앞 내용이 다시 읽어도 성립하는가 |
| 긴장 곡선 | 긴장이 오르내리는 리듬, 늘어지는 구간 |
| 위협·동기 일관성 | 위협의 크기와 인물 행동의 동기가 맞는가 (스릴러) |
| 속임수 | 눈속임(레드헤링)이 정당한가, 독자를 속이는 서술이 서술 규칙 위반인가 |

장르별 추가: 본격 추리는 단서의 공정성과 풀이 논리를 더 무겁게, 심리 스릴러는 정보 공개와 서술자 신뢰를 더 무겁게 본다.

카드 유형 후보와 형식:

| 유형 태그 | 기본 형식 | 이유 |
|---|---|---|
| 단서 누락·모호 | 지적형 | 어떤 단서를 어디에 넣을지는 작가의 설계 |
| 정보 노출 시점 | 지적형 | 의도된 긴장 설계일 수 있음 |
| 서술 속임수 위반 | 지적형 | 의도적 반칙일 수 있음 |
| 시간·장소·사실 모순 | 수정안 | 설정집·앞 회차와 대조해 확인되는 객관적 문제 |
| 과잉 설명 | 수정안(삭제 제안) | 새 문장 없이 빼기만 함 |

수정안은 단서를 새로 지어내거나 반전을 건드리지 않는다. 단서·반전에 닿는 문제는 항상 지적형이다.

### 세계형 (SF, 정통판타지)

세계 규칙이 한 번 정해진 뒤 일관되게 지켜지는지, 설정을 어떻게 독자에게 풀어 주는지를 본다. 설정집의 세계관·떡밥 모음을 규칙표로 읽는다.

| 항목 | 보는 것 |
|---|---|
| 규칙 일관성 | 기술, 사회, 물리 규칙이 회차를 건너며 바뀌지 않는가 |
| 설정 풀어 주기 | 설정이 한꺼번에 쏟아지지 않고 이야기 안에서 자연스럽게 드러나는가 |
| 개연성 | 그 세계의 규칙 안에서 사건이 성립하는가 (현실 과학 검증이 아님) |
| 파급 | 기술 하나가 사회와 인물 삶에 미치는 영향이 따져졌는가 |
| 용어 일관성 | 신조어·고유명이 같은 뜻으로 쓰이는가 |

현실 과학이 맞는지는 판정하지 않는다. AI가 틀릴 수 있어서 "참고 의견" 표시로만 언급한다.

장르별 추가: SF는 기술과 사회 규칙의 파급을, 정통판타지는 마법 체계(비용, 한계)와 종족·지리·역사 설정의 일관성, 신화적 배경을 이야기 안에서 푸는 방식을 더 무겁게 본다.

정통판타지는 웹소설에 가까운 장르다. 일반문학 엔진과는 이어지지 않고(문체형은 실험장르뿐), 웹소설 러너 위에서 웹소설 판타지 기준집(`data/genre_playbooks.json`의 `fantasy_*`)을 그대로 쓰면서 위의 세계 규칙 항목만 더한다. 정통판타지를 웹소설과 따로 장르로 둔 이유가 있어야 하므로, 웹소설을 그대로 두지 않고 세계 규칙 항목을 더해 차별점을 둔다(결정 사항 6번). 웹소설 판타지는 속도와 쾌감 중심이고, 정통판타지는 세계의 규칙과 설정이 이야기를 떠받치는지를 먼저 본다.

| 항목 (정통판타지 추가) | 보는 것 |
|---|---|
| 마법·힘의 규칙 | 비용과 한계가 정해지고 지켜지는가, 위기에서 규칙이 갑자기 바뀌지 않는가 |
| 설정의 깊이 | 종족, 지리, 역사, 신화가 이야기에 쓰이는가, 장식으로만 남지 않는가 |
| 설정 풀어 주기 | 세계 설명이 한꺼번에 쏟아지지 않고 사건 속에서 드러나는가 |
| 서사 규모 | 여정과 대립이 세계 전체의 위기와 이어지며 성장하는가 |
| 용어 일관성 | 고유명, 지명, 마법 용어가 같은 뜻으로 쓰이는가 |

카드 유형 후보: 규칙 위반(지적형), 설정 모순(수정안, 설정집·앞 회차와 대조), 설정 덤프(지적형), 용어 불일치(수정안, 토리 사전 기준).

카드 유형 후보: 설정 모순(수정안, 설정집·앞 회차와 대조), 설정 덤프(지적형, 의도된 서술일 수 있음), 규칙 위반(지적형), 용어 불일치(수정안, 토리 사전 기준).

### 문체형 (실험)

일반문학 파이프라인을 그대로 쓴다. 문체 항목 6칸, 장면 지도, 루브릭, 교정 카드, 문체 이탈 검증, 의도적 선택 제안이 모두 같다. 이 묶음에서는 장르 약속보다 문체와 작가 의도를 지키는 쪽이 앞선다.

- 실험장르는 형식 파괴 자체를 문제로 보지 않는다(의도적 선택 칸이 기본으로 열려 있다).
- 새로 만드는 것은 하위 장르 판별과 엔진 연결뿐이다. 프롬프트는 일반문학 것을 쓴다.
- 일반문학 설계 문서(`docs/literary-pipeline.md`)가 이 묶음의 설계다. 이 문서에서 다시 쓰지 않는다.

### 관계형 (로맨스)

인물 관계의 전개와 감정선을 본다. 판단 기준과 문체 기준은 기존 로맨스 기준집(`data/genre_playbooks.json`의 `romance_*`)과 `genre_clusters`의 로맨스 축(구조·배경·블렌드)을 재사용한다. 장르문학 로맨스에 이 기준집이 이미 연결돼 있는지는 구현 전에 먼저 확인한다.

| 항목 | 보는 것 |
|---|---|
| 관계의 전개 | 가까워지거나 멀어지는 이유가 장면으로 쌓였는가 |
| 감정선 | 감정이 설명에 그치지 않고 행동과 장면으로 드러나는가 |
| 갈등의 동력 | 관계를 가로막는 장애가 설득력 있는가 |
| 호흡 | 설렘, 갈등, 해소의 리듬 |

카드 유형 후보: 감정 설명 과잉(지적형), 관계 전개 비약(지적형), 호칭·말투 불일치(수정안, 설정집 대조).

## 설정집과 의도적 선택

작품 메모리는 새로 만들지 않고 기존 설정집을 쓴다. 규칙은 문학과 같다. 설정집은 전부 읽고, 새 내용은 추가만 하고, 기존 내용은 고치지 않고, 충돌은 토리 알림으로 알린다.

- 수수께끼형은 떡밥 모음을 「단서·복선 목록」으로 읽는다. 세계형은 세계관 문서를 규칙표로 읽는다.
- 장르 약속을 일부러 깬 곳을 적을 칸이 필요하다. 문체 6칸의 5번(의도적 선택)과 같은 역할이다. 작가만 쓴다.
  - 후보: 설정집에 「장르 약속」 항목을 신설하고 칸 2개를 둔다. 1) 일부러 깬 약속(예: "서술자가 독자를 속인다", "열린 결말"). 2) 지키고 싶은 약속(예: "독자가 풀 수 있게 단서를 먼저 보여 준다").
  - 1번에 적힌 것은 카드로 만들지 않는다. 리포트에서는 "의도는 알지만 이 장면에서는 전달이 약합니다" 정도로 말할 수 있다.
  - 2번은 판정 기준으로 올려 중요도를 높인다.
- 같은 유형을 반복해 거절하면 의도적 선택을 제안하는 기능(문학의 7단계)을 이 묶음에도 적용한다. 유형 태그가 달라질 뿐 같은 로직이다.

## 검증

저장 전 검증은 웹소설·문학의 기존 검사를 모두 유지한다(근거 인용 존재, 이름·용어 필터, "AI 검사, 확인 필요" 라벨). 장르 레이어는 아래를 더한다.

1. 단서·복선·사실 판정의 근거 인용이 실제 원고에 있는가 (없으면 제거)
2. 이전 회차 언급에는 모두 회차 번호가 있는가, 정보 공개 지도·요약 캐시·설정집에서 확인되지 않으면 단정 대신 질문으로 바꾼다
3. 수정안이 단서를 새로 만들거나, 반전·결말을 바꾸거나, 정보 공개 순서를 바꾸지 않았는가 (그렇다면 지적형으로 강등)
4. 장르 관습 위반을 확정 오류로 쓰지 않았는가, "의도라면 유지"가 붙어야 하는 곳에 붙었는가
5. 의도적 선택(깬 약속)에 해당하는 카드가 섞이지 않았는가

걸러진 카드는 버리지 않고 지적형으로 바꿔 살리는 것이 기본값이다.

## 구현 구조

- `genre_track.py`(새 모듈): 묶음 판별, 묶음별 설정 상수.
- `feedback_api.py`: `literary_track` 분기 옆에 `genre_track` 분기. `style`은 문학 분기로, 나머지 셋은 웹소설 러너에 장르 레이어를 얹어 실행한다.
- `feedback_pipeline/genre_layer.py`(새 모듈): 묶음별 프롬프트 조립, 카드 유형 확장, 장르 검증.
- `feedback_pipeline/prompts/genre/`: 묶음별 리포트·카드 프롬프트와 스키마.
- `data/genre_playbooks.json`: 미스터리·스릴러·SF 기준 추가는 AI 패널 쪽 튜닝에서 같이 쓸 수 있으나, 이 설계에서는 첨삭 프롬프트가 별도 파일을 쓴다(둘을 섞지 않는다).
- DB: 카드의 유형 태그가 문자열 칸인지 CHECK 제약이 있는지 확인이 필요하다. 제약이 있으면 마이그레이션(`db/NNN_…sql`)을 추가한다. `feedback_run`의 파이프라인 구분에 `genre_puzzle`, `genre_world`, `genre_relation` 값이 필요할 수 있다(문학 때 `run_kind` CHECK 마이그레이션이 필요했다).
- 화면: 카드 유형 이름과 새 설정집 칸 문구를 `ko/en/es` 로케일에 함께 추가한다. 도우미 목록과 설정집 구성은 바뀌지 않는다.

## 구현 순서와 진행 상태

- [x] 0단계 설계 확정: 열린 질문 1~3번 결정(아래 「결정 사항」)
- [ ] 1단계 기반: `genre_track()`, 하위 장르 판별, `style` 묶음을 일반문학 엔진에 연결
- [ ] 2단계 설정집 「장르 약속」 항목과 칸 2개, 문구 로케일
- [ ] 3단계 수수께끼형 리포트: 정보 공개 지도, 루브릭
- [ ] 4단계 수수께끼형 카드와 검증
- [ ] 5단계 세계형 리포트·카드·검증
- [ ] 6단계 관계형 리포트·카드·검증
- [ ] 7단계 의도적 선택 제안 연결
- [ ] 8단계 AI 패널 프롬프트 장르 튜닝 (별도 작업)

수수께끼형을 먼저 하는 이유는 판정 기준이 가장 뚜렷하고(단서가 공정한가), 웹소설 러너와의 차이가 가장 커서 장르 레이어 구조의 검증이 되기 때문이다. 문체형은 연결만 하면 되어 1단계에 같이 끝낸다.

## 테스트 계획

문학과 같은 원칙이다. 오지적을 먼저 잡고 탐지율은 그다음이다. 작가가 일부러 깬 관습을 오류로 지적하는 것이 이 파이프라인에서 가장 흔한 실패 유형일 가능성이 크다.

| 묶음 | 내용 | 측정 목적 |
|---|---|---|
| 잘 쓴 작품 | 저작권이 만료됐거나 사용 허락을 받은 장르 작품 (사용 전에 저작권 확인) | 오지적 |
| 결함 심은 작품 | 단서 누락, 정보 공개 시점 오류, 설정 모순, 방치된 복선을 일부러 삽입 | 탐지율 |
| 관습을 일부러 깬 작품 | 장르 약속을 의도적으로 깬 원고 + 「장르 약속」 칸을 채운 버전과 비운 버전 | 의도 존중 |
| 실제 사용자 원고 | 동의받은 장르문학 작가의 원고 | 실사용 가치 |

| 항목 | 재는 법 | 초기 목표 |
|---|---|---|
| 근거 인용 존재 | 자동 확인 (검증 후) | 100% |
| 심은 결함 탐지율 | 결함을 맞는 항목으로 잡은 비율 | 70% 이상 (첫 실행 후 조정) |
| 깬 약속 오지적 | 의도 칸을 채웠을 때 문제로 지적한 횟수 | 작품당 1건 이하 |
| 수정안의 단서·반전 침범 | 수정안이 단서·반전을 바꾼 횟수 | 0건 |
| 재현성 | 같은 입력 3회 실행 시 판정 일치 | 잘 작동함 ↔ 문제 뒤집힘 없음 |
| 비용·시간 | 회차 1개 기준 토큰, 소요 시간 | 기준값 기록 |

모델은 Sonnet 5로 시작하고, 후보 모델은 `tools/prompt_lab`에서 같은 조건으로 비교한다. 목표 수치는 첫 실행 후 조정할 출발점이다.

## 결정 사항

2026-10-24에 정했다.

1. **문체형 연결**: `genre_track()`이 일반문학 트랙 값을 돌려준다. `literary_track()`은 고치지 않는다.
2. **단편/장편**: 수수께끼형·세계형·관계형은 나누지 않고 회차 단위 하나로 시작한다. 장르소설은 연재형이 많아 회차 단위가 자연스럽다. 문체형만 일반문학 엔진을 따라 단편/장편을 고른다.
3. **「장르 약속」 칸**: 네 묶음 모두에 둔다. 로맨스 등에서도 관습을 일부러 깨는 작가가 있고, 칸이 있어도 안 쓰면 손해가 없다.
4. **출시 범위**: 베타 전에 전부 만든다. 장르 파이프라인 전체(1~7단계)가 베타 전에 갖춰진 채로 나간다. 베타 뒤로 미루거나 일부만 조용히 붙이지 않는다. 8단계(AI 패널 프롬프트 튜닝)는 별도 작업이라 이 범위에 넣을지 따로 정한다.
5. **정통판타지**: 웹소설 파이프라인을 그대로 두지 않고 세계 규칙 항목을 더해 차별점을 둔다. 웹소설 러너 위의 장르 레이어로 처리하고 일반문학 엔진과는 이어지지 않는다.
6. **먼저 할 일**: 불안정한 테스트 `test_cancel_keeps_saved_cards`(전체를 한꺼번에 돌릴 때만 실패)를 장르 작업 전에 고친다.

## 열린 질문

1. 카드 유형 태그에 DB 제약이 있는지 확인 후 마이그레이션 범위 확정.
2. 장르 판단 기준의 최종 목록. 위 표는 초안이며 장르 독자·작가의 의견으로 다듬어야 한다. AI가 최근 장르 경향을 보장하지 못하므로 새로움 판정은 참고 의견으로만 둔다.
3. 도우미(AI 패널) 프롬프트 튜닝(8단계)을 이 작업에 포함할지 따로 뺄지.
4. 장르문학 로맨스에 기존 로맨스 기준집이 이미 연결돼 있는지(관계형 구현 전에 확인).
5. 일반문학 엔진의 안쪽 관문이 문제다. 문체형이 쓸 일반문학 러너 5곳(`literature_runner`, `literature_long_runner`, `literature_midcheck`, `literature_style`, `literature_summary`)과 `app.py`의 작품 생성·설정 저장 코드가 모두 `literary_form.literary_track()`과 `is_literary_track_target()`로 일반문학만 통과시킨다. `genre_track()`이 값을 돌려주는 것만으로는 이 관문을 못 지나므로, (가) `is_literary_track_target()`에 "장르문학 실험" 한 조건을 더하는 안(수정 1곳, 일반문학 동작은 그대로)과 (나) 호출 지점 약 20곳을 새 판별 함수로 바꾸는 안 중에서 정해야 한다.
6. 하위 장르가 정해지지 않은 장르문학 작품(`main_genre=genre_lit`)은 묶음이 `None`이라 웹소설 러너를 탄다. 장르문학 작품은 로맨스를 교차 축(`romance_blend`: 서브플롯·공동축·메인축)으로 섞을 수 있어서, 미스터리에 로맨스 공동축이 있는 작품이 관계형 기준도 일부 받아야 하는지 정해야 한다.

## 영어·스페인어권 영향

화면 문구(카드 유형 이름, 설정집 「장르 약속」 칸, 안내)는 `ko/en/es` 로케일에 함께 추가한다. 첨삭 프롬프트와 결과는 한국어 원고를 전제로 하며, 영어·스페인어 작품 지원은 이 설계의 범위가 아니다. 출시 전 언어 검토 목록(`AGENTS.md`)에는 "첨삭 프롬프트·결과 언어"가 이미 들어 있다.
